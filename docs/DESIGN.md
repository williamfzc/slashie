# slashie：用飞书斜杠命令唤起本机 agent

一句话：发 `/前缀 内容`，本机执行对应命令，结果回帖到原消息。不建机器人、不加群、不用别人授权。

Mac 菜单栏版已跑通：`/doubao` 单条 6.8–8.8 秒回帖，多行内容和消息链接都能进上下文。记录见 `~/.fsq/fsq.log`，测试群「fsq 斜杠测试 1119」。

## 一、为什么要做

| 现状 | 带来的问题 |
|---|---|
| 平时在飞书里干活 | 想让本机 agent（豆包、codex、claude code）接着干，但不想切窗口、复制粘贴 |
| 飞书没有「本人发消息」事件 | 自建机器人只收别人 @ 它的消息，拿不到本人发出的内容 |
| 做法 | 本人身份轮询搜索 + 前缀路由 + 原消息回帖，一个账号、任何会话都能用 |

## 二、整体结构

| 层 | 目录 | 职责 | 依赖 |
|---|---|---|---|
| 外壳 | `src/app` | 菜单栏图标、状态文案、点击动作 | tauri（仅 Mac 编译） |
| 内核 | `src/runtime` | 配置、飞书调用、命令执行、轮询节奏 | lark-cli、`/bin/sh` |
| 入口 | `src/main.rs` | 单实例检查、决定跑菜单栏还是无界面常驻 | 无 |

- 内核不认识界面，Linux 上 `--no-default-features` 编译出来就是一个常驻进程，逻辑完全一样。
- 外壳只调内核的公开接口（`engine::Engine`、`config`、`poller`），不碰网络和配置细节。
- 换掉菜单栏、改成窗口或 systemd，都不用动内核；改轮询逻辑也不用碰界面。

## 三、一次触发的完整链路

| 步骤 | 做什么 | 关键设计 |
|---|---|---|
| 扫描 | 每 N 秒搜一次本人最近发出的消息 | 回看窗口 `interval × 10` 秒，最少 10 分钟；首次启动只回看 5 分钟 |
| 匹配 | 剥掉「（由豆包工作发送）」尾巴，按前缀最长优先 | 前缀后必须跟空格或结束，`/doubaoX`、`/pingpong` 不误触 |
| 造上下文 | 拼来源说明：消息链接、消息 ID、会话名、发送人 | 链接必须进命令参数，不能只躺在环境变量里 |
| 执行 | `/bin/sh -c` 执行配置里的命令 | 标准输入给空管道；标准输出、标准错误分文件存 |
| 回帖 | 回复到原消息下 | 成功只回标准输出；失败才显示错误 |
| 记录 | 消息 ID 写进 `state.json` | 重启不重复执行；单条消息只跑一次 |

## 四、配置模型

| 字段 | 含义 | 默认 |
|---|---|---|
| `poll.enabled` | 轮询开关 | `true` |
| `poll.interval` | 扫描间隔（秒） | `20` |
| `routes[].prefix` | 斜杠命令 | `/ping` |
| `routes[].cmd` | 交给 `sh` 的命令 | `echo pong {args}` |
| `routes[].dir` | 工作目录 | 家目录 |
| `routes[].timeout` | 超时秒数，到点杀进程并回已有输出 | `30` |
| `routes[].silent` | 只执行不回帖 | `false` |

### 占位符与环境变量

| 占位符 | 环境变量 | 内容 |
|---|---|---|
| `{args}` | `FSQ_ARGS` | 剥掉前缀后的全部内容 |
| `{text}` | `FSQ_TEXT` | 消息完整原文（含前缀） |
| `{link}` | `FSQ_LINK` | 这条消息的链接，拿不到时回落成会话链接 |
| `{id}` | `FSQ_ID` | 消息 ID（`om_xxx`） |
| `{context}` | `FSQ_CONTEXT` | 来源说明：链接、ID、会话、发送人 |
| `{prompt}` | `FSQ_PROMPT` | 内容 + 空行 + 来源说明，直接丢给 agent |

- 给 agent 类命令用 `"$FSQ_PROMPT"`，链接跟着进上下文
- 只要你输入的内容用 `"$FSQ_ARGS"`

## 五、关键取舍

| 问题 | 选择 | 为什么 | 代价 |
|---|---|---|---|
| 怎么知道自己发了消息 | 定时轮询搜索 | 飞书没有本人消息事件；机器人只能收别人 @ 它的 | 有秒级延迟；频率要克制 |
| 用什么身份 | lark-cli 的本人凭据 | 不打扰会话，不用把机器人拉进群 | 依赖凭据权限 |
| 去重放哪 | 每台机器一份 `state.json` | 实现简单，无中心依赖 | 两台同时开会各回一次 |
| 子进程标准输入 | 空管道，不用 `/dev/null` | 豆包命令行拒收 `/dev/null`，报「无法以 UTF-8 格式读取标准输入」 | 多一行代码 |
| 输出怎么收 | stdout / stderr 分两个文件 | 豆包会把内部状态写进 stderr，合在一起会污染回帖 | 失败时只给错误，不带正常输出 |
| 怎么防重复启动 | `~/.fsq/app.pid` + 进程探活 | 避免两份进程抢同一条消息各回一次 | 跨机不共享 |

## 六、运行与文件

| 路径 | 作用 |
|---|---|
| `~/.fsq/config.json` | 配置，首次启动自动生成并回填身份 |
| `~/.fsq/state.json` | 已处理消息 ID，上限 2000 条 |
| `~/.fsq/fsq.log` | 运行日志，带秒级时间戳，超过 2MB 截半 |
| `~/.fsq/app.pid` | 单实例锁，固定在真实家目录，与配置目录无关 |
| `~/.fsq/_out.tmp` / `_err.tmp` | 命令输出暂存，避免管道写满卡死 |

### Mac 启动方式

- 双击 `fsq.app`：菜单栏出现 `/` 图标，菜单里有状态、轮询开关、间隔（10/20/30/60 秒）、打开配置、打开日志、退出。
- `./fsq --headless`：无界面常驻，日志同步打到终端，方便调试和 Linux 上跑。

## 七、已知限制

| 限制 | 影响 | 规避 |
|---|---|---|
| 从临时会话启动会继承短期身份 | 十几分钟后报 `temporary token expired`，整轮失效 | 用菜单栏版独立启动，凭据长期有效 |
| 只扫本人发出的消息 | 别人发的不触发 | 设计如此，避免变成公共机器人 |
| 回看窗口有限 | 进程停太久会漏消息 | 别长时间关；需要补历史另说 |
| 去重不跨机 | 两台机器同时开，各回一次 | 只在一台开 |
| 依赖 lark-cli 权限 | 换机器可能缺 `im:message.send_as_user` | 补权限或换带权限的凭据 |

## 八、后续

- Mac 优先：开机自启（加入登录项）、间隔与开关即时生效、配置热更新，已经具备。
- Linux：同一份内核源码，`cargo build --release --no-default-features` 即可，不需要界面依赖。
- 路由扩展：`/codex`、`/claude code` 只是再加一条配置，不需要改代码。

## 待决策

- 回帖失败要不要加系统通知：现在只写日志，菜单栏不提示。需要通知就加，代价是多一个系统权限。
- 要不要多机共享去重：需要中心存储或同步机制，当前不做。
